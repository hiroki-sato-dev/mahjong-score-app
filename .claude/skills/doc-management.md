# ドキュメント管理ルール

## ファイルの役割と更新タイミング

| ファイル | 役割 | 更新タイミング |
|---|---|---|
| `README.md` | プロジェクト概要・セットアップ | 技術スタックや起動手順が変わったとき |
| `DEVELOPMENT.md` | 開発フロー・コマンド説明 | ワークフローやコマンドが変わったとき |
| `docs/spec/SPEC.md` | マスター仕様書 | `/spec-done` 実行時（機能完了時） |
| `docs/spec/features/*/spec.md` | 作業中の機能仕様 | 機能着手〜完了まで |
| `docs/design/REFERENCE.md` | 実装リファレンス | `/doc-sync` 実行時 |

## REFERENCE.md の更新ルール

### 更新するもの
- コンポーネントのProps定義（実際のコードと一致させる）
- 型定義（`types/index.ts` と同期）
- ルーティング表（新しいページが追加されたとき）

### 更新しないもの
- デザイントークン（カラー・フォント）：原本から変えない
- `lib/points.ts` の計算ロジック：仕様変更がない限り変えない

## ドキュメントのフォーマット規則

- 見出しは `##` から始める（`#` はファイルタイトルのみ）
- コードブロックには言語を指定する（`typescript`, `bash` など）
- テーブルを使って情報を整理する
- 日本語で記述する

## 注意事項

- ドキュメントとコードの乖離を防ぐため、実装完了時に必ず `/doc-sync` を実行する
- `docs/spec/features/` に残っているディレクトリ = 作業中の機能
- SPEC.md は「現在実装済みの仕様」のみを記載する（未実装の仕様は features/ に置く）
